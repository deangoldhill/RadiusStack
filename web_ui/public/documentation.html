Scope, Global, default tenant, and multi-tenant operation

With multi-tenancy disabled, RadiusStack is one default/global environment and no tenant selector is shown. Enabling Multi-tenant mode preserves platform-wide configuration in Global and isolates tenant-aware users, MAC devices, plans, profiles, NAS clients, and their operational records by active tenant.

Work safely

  • Super administrators select Global or a tenant in the sidebar. Global is a platform ownership domain, not an “all tenants” aggregate for operational records; Global also permits selected cross-tenant read-only dashboard summaries, Auth Logs, Accounting History and the Audit Log; use each record's Tenant label to identify ownership. The Global Failed Authentication Analysis is currently limited to default/unattributed rows, so select a tenant to inspect its failures.
  • Tenant administrators are limited to assigned tenants and cannot select Global or change tenant membership.
  • Use Tenants to create, rename, describe, delete tenants and assign administrators. Deleting a tenant permanently removes its identities, NAS and proxy configuration, usage, authentication/accounting history, settings, memberships and tenant-attributed audit entries. Back up required records before deletion.
  • Before creating users, NAS clients, plans, or profiles, confirm active tenant. Same-named objects can independently exist in separate scopes.
  • Platform settings, certificates and backups are Global-only. Audit Log shows the selected tenant's activity in tenant context and all tenant-attributed activity in Global; tenant RadSec CA controls appear only in an active tenant.

Global-only (super administrator)

Use Global for platform configuration, tenant management, certificates, backups and HA controls. Global is not an all-tenant view of users, plans or depleted allocations: select an individual tenant to view or change those records. Global also provides read-only cross-tenant dashboard summaries, Auth Logs and Accounting History with Tenant labels; operational writes remain tenant-scoped.

Selected tenant

Choose an assigned tenant before opening Users, MAC Auth, Plans, Profiles, NAS Clients, Downstream Proxy, depleted-allocation reports or tenant RadSec controls. Requests use that tenant's scope; a tenant administrator cannot switch to Global. With multi-tenancy disabled, there is no tenant selector and the legacy single-environment workflow remains available.

Monitor activity

Dashboard

High-level RADIUS authentication, users, NAS clients and recent activity. In a selected tenant, the Dashboard previews depleted users and MAC devices with per-plan counts; Reports has the complete paginated detail, and Plans has sortable depleted counts. This widget is hidden in Global. Manual refresh remains available; auto-refresh is enabled by default and can be toggled off. Global-only Server Health shows the RADIUS container's Docker-reported state, uptime, CPU and memory (not host-wide telemetry); stack status is healthy only when all expected containers are running and otherwise Degraded; this is not the Docker healthcheck status. Tenant views do not request it.

Active Sessions

Find open accounting sessions with Username, NAS IP, Calling Station ID, and Framed IP. Select rows only after confirming matches; session-clearing actions change accounting state. Rows controls pagination.

Reports

Use Stats Date From/To to bound statistics and Username, Start, End for user/accounting reports. Blank filters do not constrain results. Depleted allocations lists users and MAC Auth devices whose current-cycle data or time use reached a finite plan allowance, with per-plan totals, filters, and paginated detail; 0 means unlimited. The User-Specific Executive Report shows current plan usage against its allocation independently of its historical date filter. Counts honor the selected tenant. In Global, only the permitted read-only operational summary routes are available; select a tenant for depleted-allocation detail and per-user reports.

Users, MAC devices, plans, and profiles

Users

Create/edit RADIUS credentials, import CSV, filter by text/plan/profile/TOTP state, and paginate. Fields: Username (unique identity), Password, optional Static IP, Plan, and Profile. A user's TOTP enrollment switch issues a setup link and code; Pending means enrollment is unfinished, and Reset Key requires re-enrollment. This is separate from administrator 2FA. Reset Usage establishes a new plan usage baseline without deleting historical accounting; Reset Usage Selected applies only to selected rows on the current page. Review scope/filters before bulk import or deletion.

MAC Auth

Manage devices authenticated by MAC rather than typed password. Search/filter by device ID, address, profile, plan; import CSV as needed. Fields: MAC ID, MAC address, optional static IPv4 address, plan and profile. Use colon-separated MAC format. Reset Usage establishes a new plan usage baseline without deleting historical accounting; Reset Usage Selected applies only to selected rows on the current page.

Plans

Plan Name is assignable. Data Limit (MB) and Time Limit (Hours) accept 0 for unlimited. Automatic Reset Period renews counters. The sortable Depleted Users column counts assigned users and MAC devices whose data or time allowance has been exhausted since their plan usage baseline; an unlimited allowance (0) never depletes. Click a plan for summary counts and its top ten assigned identities by data usage; use Reports for complete filterable depleted-allocation detail. Disconnect toggles enforce immediate PoD when data/time is exhausted. Search/Rows only change the listing.

Profiles

Profiles return reusable RADIUS reply attributes. Set Profile Name; optionally restrict NAS IPs or CIDR ranges, or select Allow all NAS; return optional VLAN ID; add supported reply attribute/value pairs. Use only attributes your NAS understands.

Network access: NAS clients and RadSec

NAS Clients

Required on NAS creation: IP Address (nasname), Shortname, Shared Secret; Description documents the client. On edit, leave Shared Secret blank to keep the existing value; enter a new one only to replace it. Clone reuses source configuration but requires a distinct address and name; NAS cloning does not duplicate an IP.

TLS (RadSec) exposes P12 (password-protected bundle) or PEM (separate certificate/key). Download shared RadSec server trust CA so the NAS validates the listener, then generate NAS client credentials. Encrypted private-key passphrases are secrets: newly generated passphrases are shown at issuance, and an authorized NAS reader can reopen a supported NAS certificate to reveal its stored passphrase later. Legacy or unrecoverable passphrases require regeneration. Downloads use authenticated one-time tokens with a 10-minute validity window; save the artifacts promptly. Tenant RadSec provides per-tenant client CA provisioning, CA rotation (which invalidates existing NAS clients), proxy enrollment tied to the observed client IP, and credential sets that can be assigned to NAS clients. Advanced CoA/PoD attributes control dynamic authorization; select a live session and confirm the target before requesting a disconnect or authorization change.

Downstream Proxy

In the selected tenant, add a destination IPv4, authentication/accounting ports, shared secret and Traffic selection (Auth, Accounting or Both); the stored secret is write-only. Assign a destination on a NAS or user Profile. For a known user, the Profile route takes precedence over the packet-source NAS route; unknown users use the NAS route. The current synchronous downstream helper permits PAP authentication only in Duplicate request mode with validate proxy response enabled; a downstream reject or timeout fails closed. It permits proxy-only accounting with validation off: a downstream acknowledgement is required, while local accounting is also recorded for plan usage. A destination restricted to Accounting cannot carry authentication, and one restricted to Auth cannot carry accounting. Saving or deleting a destination activates the local Radius configuration before reporting success; a saved-but-inactive response requires operator review. On an updated HA secondary, committed destination replay also activates its own Radius instance, with retry if activation fails. NAS/Profile route-only changes do not trigger that destination restart.

Logs, accounting, audit, and API testing

Auth Logs

Investigate attempts using Username, NAS IP Address, Calling Station ID, Called Station ID, Date From/To, Result, Rows per page. The Server column identifies the member that handled each authentication (Server 1 or Server 2, based on its stable HA database offset, not its current Primary/Secondary role). Records created before origin tracking show Unknown. Retention is configured in Global Settings. In a selected tenant, Delete Filtered Logs permanently deletes matching attempts; with no filters it targets every auth log in that tenant. Verify the filters and confirmation before deleting. Global operational log views are read-only.

Accounting History

Review starts/stops/consumption with Username, NAS Client, Start Date, End Date; sort columns and open row details. Delete Filtered Records is destructive and requires at least one filter.

Audit Log

Search administrator action history by username/action/details, outcome, date range and rows. In a tenant, only that tenant's activity is shown. In Global, every tenant's entries and platform actions appear together with the correct Tenant label; older unattributed rows cannot be reconstructed reliably. Use it before correcting configuration.

API Documentation & Tester

Filter routes, choose Method, replace placeholders in Path, enter optional JSON Body, then select Send request. Route selection only stages an example; Send request executes the current method, path and body immediately, including destructive writes, without a second confirmation. Verify scope and payload first. Current tenant context contributes the tenant header for tenant-aware routes.

Administrators, settings, backup, certificates, and TOTP

Administrators

Create accounts with Username/Password; choose Global Access Level, module permissions, tenant memberships, super-admin status, first-login 2FA. In a selected tenant, authorized administrators manage only non-super-admin accounts exclusive to that tenant; Global super administrators manage membership and platform super-admin status. Gen API Key immediately invalidates the previous key, so securely capture its one-time display and update integrations. Capture new 2FA QR/secret at issuance; disabling administrator 2FA requires Settings read-write permission. Use least privilege. Administrator TOTP provisioning can import an existing enrolled seed through an authorized admin action; never put a real seed in an API docs example. Tenant enforcement of 2FA affects assigned administrators. Sidebar Profile shows your username, lets you change your own password, and stores your personal colour scheme; other administrators keep the default unless they choose their own. Global Settings can set the platform default.

Settings

  • Global platform/UI: multi-tenant mode, platform default theme, Radius/API debug and TOTP enrollment lifetime.
  • Selected tenant: enforce administrator 2FA, password masking, custom reply attributes, MAC auto-create defaults/interval, stale-session clearing and tenant RadSec enablement. These settings are not changed by editing Global platform defaults.
  • Attribute catalogue/custom VSA: search standard/vendor attributes; define vendor label/code, attribute number, name, type only from vendor documentation.
  • Syslog / SIEM forwarding (Global only): enable the saved destination, choose UDP or TCP, and separately select audit actions and RADIUS authentication attempts. Events include their tenant ID; auth messages include NAS, calling/called station, reply, reply message and timestamp. Save before using Send Test Message, which uses the saved destination and reports TCP connection/send errors. UDP send success only confirms local socket acceptance, not collector ingestion. Auth events retain a database checkpoint across restarts and retry on a failed send; retain auth rows until they are forwarded if reliable recovery matters. Administrative audit forwarding is best-effort at send time and has no replay cursor.
  • Global retention: auth-log retention/check and Radius statistics retention/purge/polling. Tenant stale-session thresholds and worker interval are set in the selected tenant.
  • Backup/restore: full/partial sets; restore only verified JSON backups.
  • Certificates: generate subject Country/State/City/Organization/Common Name/FQDN or upload matching certificate/key and optional password. Changes affect client trust.
  • Tenant RadSec CA: in active tenant enable/provision/download CA. Rotation invalidates tenant NAS client certificates; issue replacements.

Container operations (Global-only)

Global Settings shows RadiusStack container states and recent logs. Restart is a disruptive Settings read-write action; this is separate from Dashboard Server Health.

High availability (Global-only)

A Global super administrator with Settings permission can view HA status, pause/resume delivery, request a full sync or a certificate bundle, and perform promotion/demotion or log reconciliation only after reviewing the target nodes. A full sync is initiated on the primary; promotion and reconciliation are operational actions, not tenant changes. Both nodes need compatible updated code. With HA enabled, committed primary configuration/accounting changes flow to the secondary; authentication and accounting rows generated on the secondary are queued back to a primary-only receiver. The primary acknowledges reverse log batches after transactional replay. A conflicting accounting-session identity stops that batch and leaves it queued for operator reconciliation; do not assume it was synchronized. A paused or unreachable peer leaves pending work for retry. Tenant RadSec CA/trust material is transferred over the encrypted HA channel, but each node retains its own listener identity; provisioning a NAS client certificate is a separate action. These are implementation behaviors, not evidence of a completed live HA failover test on this dev installation.

Login and TOTP setup

Login accepts administrator Username/Password then six-digit setup/verification code when required. TOTP setup needs RADIUS Password, administrator-issued setup code, manual secret fallback, current six-digit code. Never share secrets or codes.
