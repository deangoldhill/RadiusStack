Scope, Global, default tenant, and multi-tenant operation

With multi-tenancy disabled, RadiusStack is one default/global environment and no tenant selector is shown. Enabling Multi-tenant mode preserves platform-wide configuration in Global and isolates tenant-aware users, MAC devices, plans, profiles, NAS clients, and their operational records by active tenant.

Work safely

  • Super administrators select Global or a tenant in the sidebar. Global is a platform ownership domain, not an “all tenants” aggregate for operational records; the Global Audit Log is the exception and shows tenant-attributed audit entries across all tenants.
  • Tenant administrators are limited to assigned tenants and cannot select Global or change tenant membership.
  • Use Tenants to create, rename, describe, delete tenants and assign administrators. Confirm destructive consequences before deletion.
  • Before creating users, NAS clients, plans, or profiles, confirm active tenant. Same-named objects can independently exist in separate scopes.
  • Platform settings, certificates and backups are Global-only. Audit Log shows the selected tenant's activity in tenant context and all tenant-attributed activity in Global; tenant RadSec CA controls appear only in an active tenant.

Monitor activity

Dashboard

High-level RADIUS authentication, users, NAS clients, recent activity, and a current-cycle depleted-allocation widget grouped by Users, MAC Auth devices, and plan. Manual refresh remains available; auto-refresh is enabled by default and can be toggled off. Global-only Server Health shows the RADIUS container's Docker-reported state, uptime, CPU and memory (not host-wide telemetry); a container without a Docker healthcheck shows health as Unknown, not failed. Tenant views do not request it.

Active Sessions

Find open accounting sessions with Username, NAS IP, Calling Station ID, and Framed IP. Select rows only after confirming matches; session-clearing actions change accounting state. Rows controls pagination.

Reports

Use Stats Date From/To to bound statistics and Username, Start, End for user/accounting reports. Blank filters do not constrain results. Depleted allocations lists users and MAC Auth devices whose current-cycle data or time use reached a finite plan allowance, with per-plan totals, filters, and paginated detail; 0 means unlimited. The User-Specific Executive Report shows current plan usage against its allocation independently of its historical date filter. Counts honor the selected tenant, and Global displays platform-owned records only.

Users, MAC devices, plans, and profiles

Users

Create/edit RADIUS credentials, import CSV, filter by text/plan/profile/TOTP state, and paginate. Fields: Username (unique identity), Password, optional Static IP, Plan, and Profile. Review scope/filters before bulk import or deletion.

MAC Auth

Manage devices authenticated by MAC rather than typed password. Search/filter by device ID, address, profile, plan; import CSV as needed. Fields: MAC ID, MAC address, optional static IP, plan, profile, enabled state. Use colon-separated MAC format.

Plans

Plan Name is assignable. Data Limit (MB) and Time Limit (Hours) accept 0 for unlimited. Automatic Reset Period renews counters. Disconnect toggles enforce immediate PoD when data/time is exhausted. Search/Rows only change the listing.

Profiles

Profiles return reusable RADIUS reply attributes. Set Profile Name; optionally restrict NAS IPs or select Allow all NAS; return optional VLAN ID; add supported reply attribute/value pairs. Use only attributes your NAS understands.

Network access: NAS clients and RadSec

NAS Clients

Required on NAS creation: IP Address (nasname), Shortname, Shared Secret; Description documents the client. On edit, leave Shared Secret blank to keep the existing value; enter a new one only to replace it. Clone reuses source configuration but requires a distinct address and name; NAS cloning does not duplicate an IP.

TLS (RadSec) exposes P12 (password-protected bundle) or PEM (separate certificate/key). Download shared RadSec server trust CA so the NAS validates the listener, then generate NAS client credentials. Private-key passwords are secrets and shown only at generation. Tenant RadSec provides per-tenant client CA provisioning, CA rotation (which invalidates existing NAS clients), proxy enrollment tied to the observed client IP, and credential sets that can be assigned to NAS clients. Advanced CoA/PoD attributes control dynamic authorization; select a live session and confirm the target before requesting a disconnect or authorization change.

Downstream Proxy

In the selected tenant, add destination IPv4, authentication/accounting ports and a shared secret; the stored secret is never displayed. Assign a destination on a NAS or a user Profile. For a known user, the Profile route takes precedence over the packet-source NAS route; unknown users use the NAS route. Routed authentication is PAP-first. In proxy only mode the downstream server decides authentication. Duplicate request runs local processing and forwards a copy; select validate proxy response to require an authenticated downstream accept as well. A reject or timeout fails closed when validation is selected. Proxy-only accounting requires a downstream acknowledgement and also writes local accounting so new data usage counts against the plan. Check destination activation before sending traffic.

Logs, accounting, audit, and API testing

Auth Logs

Investigate attempts using Username, NAS IP Address, Calling Station ID, Called Station ID, Date From/To, Result, Rows per page. Retention is configured in Settings.

Accounting History

Review starts/stops/consumption with Username, NAS Client, Start Date, End Date; sort columns and open row details. Delete Filtered Records is destructive and requires at least one filter.

Audit Log

Search administrator action history by username/action/details, outcome, date range and rows. In a tenant, only that tenant's activity is shown. In Global, every tenant's entries and platform actions appear together with the correct Tenant label; older unattributed rows cannot be reconstructed reliably. Use it before correcting configuration.

API Documentation & Tester

Filter routes, choose Method, replace placeholders in Path, enter optional JSON Body, then select Send request. Marked write operations are not sent until selected. Current tenant context contributes the tenant header for tenant-aware routes.

Administrators, settings, backup, certificates, and TOTP

Administrators

Create accounts with Username/Password; choose Global Access Level, module permissions, tenant memberships, super-admin status, first-login 2FA. Use least privilege. Administrator TOTP provisioning can import an existing enrolled seed through an authorized admin action; never put a real seed in an API docs example. Tenant enforcement of 2FA affects assigned administrators. Sidebar Profile shows your username, lets you change your own password, and stores your personal colour scheme; other administrators keep the default unless they choose their own. Global Settings can set the platform default.

Settings

  • Platform/UI: multi-tenant mode, theme, enforce 2FA, password masking, Radius/API debug, TOTP enrollment lifetime.
  • Attribute catalogue/custom VSA: search standard/vendor attributes; define vendor label/code, attribute number, name, type only from vendor documentation.
  • Syslog / SIEM forwarding (Global only): enable the saved destination, choose UDP or TCP, and separately select audit actions and RADIUS authentication attempts. Events include their tenant ID; auth messages include NAS, calling/called station, reply, reply message and timestamp. Save before using Send Test Message, which uses the saved destination and reports TCP connection/send errors. UDP send success only confirms local socket acceptance, not collector ingestion. Auth events retain a database checkpoint across restarts and retry on a failed send; retain auth rows until they are forwarded if reliable recovery matters. Administrative audit forwarding is best-effort at send time and has no replay cursor.
  • MAC auto-create: enable, default profile/plan, worker interval.
  • Retention: stale-session thresholds/interval; auth-log retention/check; stats retention/purge/polling.
  • Backup/restore: full/partial sets; restore only verified JSON backups.
  • Certificates: generate subject Country/State/City/Organization/Common Name/FQDN or upload matching certificate/key and optional password. Changes affect client trust.
  • Tenant RadSec CA: in active tenant enable/provision/download CA. Rotation invalidates tenant NAS client certificates; issue replacements.

Login and TOTP setup

Login accepts administrator Username/Password then six-digit setup/verification code when required. TOTP setup needs RADIUS Password, administrator-issued setup code, manual secret fallback, current six-digit code. Never share secrets or codes.
